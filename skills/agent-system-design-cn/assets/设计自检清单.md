# 设计自检清单

用于第 7 步自检，也用于评审已有设计。先判定 Agent 类型并选出维度，再逐项检查、打分、分级。

## 目录

1. 使用方法
2. 类型与维度选择
3. 评分等级
4. 基础维度 1-7（所有 Agent 必评）
5. 进阶维度 8-14（按类型选评）
6. 扩展维度 15-21（按需选评）
7. 交付前硬性检查
8. 评审报告格式

## 1. 使用方法

1. 判定 Agent 类型（可多选），按第 2 节选出要评的维度。
2. 逐维度对照检查项。每项回答「满足 / 部分满足 / 不满足 / 不适用」，并指出设计文档中的依据位置。
3. 按该维度的评分标准打 0 至 5 分。分数必须有依据。设计中遗漏的，按缺失打分；因用户未提供材料而无法判断的，记为「待核实」，不打分、不计入均分，并列出需要补充的材料。
4. 对照反模式列表，命中的写进「识别的反模式」。
5. 把问题分为三级：
   - 严重：会导致错误结果、安全事故、成本失控或无法上线，必须修复。
   - 中等：影响质量、稳定性或可维护性，建议修复。
   - 轻微：可选优化。
6. 过一遍第 7 节的硬性检查，未通过的项直接记为严重问题。

不适用和待核实的维度都不打分，也不计入均分，但要分别写明不适用的理由和需要补充的材料。依据标清设计声明、推演或实际验证；文档得分只评文档，与模型成功率和发布许可分开；未运行和评分无效分别记录、不计入通过，严重硬失败单独判定。

## 2. 类型与维度选择

| Agent 类型 | 典型特征 | 必加维度 |
|---|---|---|
| 单任务 Agent | 只处理一类任务，无复杂流程 | 1-7 |
| 工作流 Agent | 多步执行链、条件分支 | 1-7、10、11 |
| 工具使用 Agent | 接入外部 API、工具、数据库 | 1-7、10、13、15 |
| 检索增强 Agent | 依赖知识检索生成 | 1-7、8、17 |
| 对话式 Agent | 多轮对话、维护上下文 | 1-7、8、13 |
| 多 Agent 系统 | 多个协作 Agent | 1-7、10、11、18、20 |
| 自主或自适应 Agent | 学习、规划、自我改进 | 1-7、9、12、16、21 |
| 生产级 Agent | 面向生产部署，要求高可靠 | 1-7、10、11、13、14、19 |

基础维度 1 至 7 始终检查，但先判断设计是否需要该能力。不需要且有理由时（例如单次调用不需要工具、规划或反思；单 Agent 不需要协作），记为不适用、不打分；需要却缺失时，才按评分标准打低分。各维度评分表中的 0 分只适用于「需要却缺失」的情况。

## 3. 评分等级

| 分数 | 等级 | 含义 |
|---|---|---|
| 0 | 缺失 | 完全没有考虑 |
| 1 | 初级 | 有意识但做法不当 |
| 2 | 基础 | 有基本实现，存在明显缺陷 |
| 3 | 良好 | 核心完善，缺部分进阶特性 |
| 4 | 优秀 | 完备合理 |
| 5 | 卓越 | 最佳实践，可作为范例 |

综合得分为已评维度的算术平均，保留一位小数。评级按综合得分四舍五入后的整数对应上表等级（如 3.6 记为 4 优秀）；严重问题未修复时，评级后注明“未通过”。

## 4. 基础维度 1-7

### 维度 1：任务分解（提示链）

只评需要固定多步分解的任务。按有意义的产物拆步骤；专家角色、独立 Agent 和 JSON 正文都属可选。

检查项：
- [ ] 多步分解有明确收益，节点职责与产物清楚，普通转换可直接用代码
- [ ] 关键控制字段有类型与校验，正文格式适合消费者
- [ ] 依赖、原始目标、硬约束与必要更早产物显式传递，引用可读且版本可核对
- [ ] 必要关卡区分格式、业务及产物可用性，失败可定位并有有界处理与终止出口
- [ ] 每一步的信息充分且精简，下游不只收到上一步转述

反模式：多节点只做转述；顺序执行代替数据依赖；缺原始目标；格式通过当事实正确；为得分增加专家人设或独立 Agent。

| 分 | 标准 |
|---|---|
| 0 | 需要多步分解却缺失 |
| 1 | 步骤模糊，依赖或关键数据不清 |
| 2 | 基本分解，但产物、输入或校验有明显缺口 |
| 3 | 职责与依赖清晰，必要关卡或失败出口仍不足 |
| 4 | 划分、输入、交接、校验、上下文及失败上限齐全 |
| 5 | 在 4 分基础上验证了依赖缺失、错误传播及超限边界；专家角色和多 Agent 属可选 |

### 维度 2：路由

只在不同输入或状态需要不同处理路径时评估。单一可靠方法足够时直接使用，混合分类、多层路由和动态扩展属可选。

检查项：
- [ ] 允许类别、分类方法与处理器职责匹配，返回经枚举校验，不执行模型生成的任意入口
- [ ] 未知、模糊、多意图、非法输出及分类失败有明确兜底
- [ ] 路由判断与业务职责可分别检查，原始请求与必要材料传给处理器
- [ ] 处理器仍校验权限与审批，业务动作的授权另行检查
- [ ] 准确率及适用阈值通过样例验证，自报置信度经校准后才当概率使用

反模式：类别不同但处理相同；多意图静默丢失；未知请求默认高风险动作；为得分混合多方法；路由绕过审批。

| 分 | 标准 |
|---|---|
| 0 | 需要区分路径却无有效路由 |
| 1 | 有分支但职责或类别不清 |
| 2 | 基本分类可用，兜底或关键输入有明显缺口 |
| 3 | 分类与职责清晰，适用的多意图、失败或授权边界不足 |
| 4 | 必要分类、允许集合、职责、兜底、输入与权限边界齐全 |
| 5 | 在 4 分基础上验证了所需分类质量及边界；多种方法、多层路由和动态扩展属可选 |

### 维度 3：并行化

只在存在相互独立的子任务、且并发确有时延或覆盖收益时评估；也包括对同一任务多次执行再投票。串行足够或依赖紧密时记不适用，得分与是否并行无关。

检查项：
- [ ] 正确识别了不依赖其他步骤的独立子任务
- [ ] 并行结束后有结果聚合机制
- [ ] 使用了异步或并发执行
- [ ] 有依赖的步骤保持顺序，独立步骤并行
- [ ] 并行结果能可靠地传给后续步骤
- [ ] 单个并行分支失败时的处理方式已定义

反模式：把有依赖的步骤强行并行，导致数据不一致；忽视并发带来的调试和日志复杂度；大量独立子任务仍全部串行。

| 分 | 标准 |
|---|---|
| 0 | 需要并行收益却全部串行，未考虑并行 |
| 1 | 意识到可并行，但实现不正确或缺聚合 |
| 2 | 有基本并行，但独立性判断或聚合逻辑有误 |
| 3 | 正确识别并并发执行、有聚合，但缺状态管理或错误处理 |
| 4 | 独立性判断准确、异步执行、聚合清晰、状态传递可靠 |
| 5 | 在 4 分基础上验证了分支失败、部分结果聚合与并发上限；并行度按需设定 |

### 维度 4：反思（评估-优化）

仅在明确标准、可执行反馈与迭代价值存在时评估。生产与检查分开，可用代码、测试、单独模型评审或人工，永久评审 Agent 属可选；需要修正时，只迭代确有问题的输出。

检查项：
- [ ] 评审依据原始需求、约束、对应版本候选及必要证据，不以生成者自述代替验收
- [ ] 反馈有具体位置、问题与建议，控制结论有字段定义，格式错误按未通过处理
- [ ] 修改后重新检查对应版本，旧评分不贴给新候选
- [ ] 通过、无法修复、停滞与超限都有去向，局部迭代与任务总预算有硬边界
- [ ] 保留必要版本和未决事项，预留最终检查预算，不交付未经检查的新产物冒充通过

反模式：单次生成一概判错；自述满意即通过；评审看不到必需事实与测试；旧评分验新版；无限循环；必须多 Agent 才能得高分。

| 分 | 标准 |
|---|---|
| 0 | 需要反馈修正却没有有效机制 |
| 1 | 有自检但标准或可信检查不足 |
| 2 | 有评审和修改，反馈、版本或预算有明显缺口 |
| 3 | 职责与反馈清晰，必要最终检查或停止出口仍不足 |
| 4 | 标准、证据、版本、反馈、最终检查和预算边界齐全 |
| 5 | 在 4 分基础上验证了必要迭代的效果及失败边界；不同模型和独立 Agent 属可选 |

### 维度 5：工具使用

让模型按需请求外部能力，由宿主真实执行；必要时把结果交回模型继续处理。只评任务需要的能力，评分与工具数量、链式调用和额外的模型整合无关。

检查项：
- [ ] 每个工具写明功能、产出、触发时机和边界，参数类型、范围及默认值由宿主校验
- [ ] 工具执行与模型决策分离，副作用、身份、读写范围和必要审批受宿主或服务约束
- [ ] 返回区分空结果、截断、失败及结果未知，错误信息能指导允许的下一步
- [ ] 结果真实且适合消费者；需要模型继续处理时回填结果，可直接交付的产物直接交付
- [ ] 凭据和可信调用身份由系统管理，不让模型生成或进入提示词
- [ ] 返回有大小限制、必要证据及继续读取入口，外部调用有超时

反模式：工具描述模糊；模型文字模拟执行；静默失败或截断；凭模型参数认定授权；写入结果未知就盲重试；为高分增加多工具或无必要的模型整合。

| 分 | 标准 |
|---|---|
| 0 | 需要外部能力却缺失或无法真实执行 |
| 1 | 有工具但描述或边界模糊，关键参数依靠猜测 |
| 2 | 能力基本匹配，但校验、错误或结果处理有明显缺口 |
| 3 | 契约与执行清晰，适用的权限、失败或超时边界仍有缺口 |
| 4 | 必要工具、参数校验、真实返回、错误去向、权限和超时齐全 |
| 5 | 在 4 分基础上，代表性、边界和失败用例验证了必要工具的行为；多工具和链式调用属可选 |

### 维度 6：规划

只在需要根据请求或环境生成任务与依赖时评估；成熟固定流程记不适用。规划、校验和执行是逻辑阶段，可由同一 Agent 承担，重规划只在证据使计划失效时进行。

检查项：
- [ ] 说明动态计划必要性，任务、输入、产物、验收与依赖可执行
- [ ] 派发前校验身份、引用、依赖、范围、任务数及预算，权限只由可信系统授予
- [ ] 只执行当前有效计划中依赖就绪的项目
- [ ] 证据使假设或路线失效时明确修订原因，重算顺序并判断已完成项是否仍有效
- [ ] 目标、审批及总预算不被重置，范围变更先确认，不在旧遍历列表上仅替换计划变量

反模式：简单任务必配 Planner；失败就重写全计划；初始计划失效仍机械执行；动态依赖沿旧顺序执行；重规划扩大目标或权限。

| 分 | 标准 |
|---|---|
| 0 | 需要计划却只有无目标的即时反应 |
| 1 | 有步骤列举但缺可执行依赖 |
| 2 | 基本计划可用，校验、依赖或范围有明显缺口 |
| 3 | 计划与执行清晰，必要变更或预算处理仍不足 |
| 4 | 必要动态计划、校验、就绪调度、修订和范围预算边界齐全 |
| 5 | 在 4 分基础上验证了依赖变化、失效假设和超限边界；独立 Planner 和每轮重规划属可选 |

### 维度 7：多 Agent 协作

只评确需多个 Agent 的设计。角色、节点与实例分开判断，评分与混合模式、持久人格、扩展能力和永久协调/验证角色的数量无关。

检查项：
- [ ] 每个 Agent 有实际上下文、工具或权限隔离及简单替代不足的理由，职责、产物负责人和接纳者清楚
- [ ] 协调结构匹配任务，固定链可由宿主协调，转派或嵌套有允许关系、深度与共享预算约束
- [ ] 自包含派发保留七要素、原始目标、必要规范及可读的更早产物，不假设继承历史
- [ ] 交接业务字段、可信任务/实例/作用域、证据及必要版本可核对，执行成功之外另有业务验收
- [ ] 共享状态的负责人、读写范围、发布入口与所需并发规则清楚，权限不只依赖提示词
- [ ] 必要失败和缺口有返回去向，关键产物缺失不静默降级为完整成功；重复及迟到结果按适用规则接纳

反模式：按岗位或文件数拆分；多个 Agent 只互相转述；只有路径无读取能力；任务与版本串用；无限转派；为高分要求混合交互或跨系统协议。

| 分 | 标准 |
|---|---|
| 0 | 确需协作却缺少有效分工与交接 |
| 1 | 有多个 Agent，但职责与协调不清 |
| 2 | 基本分工可用，输入、交接或权限有明显缺口 |
| 3 | 职责与交互合理，适用的接纳、状态或失败边界仍不足 |
| 4 | 必要角色、派发、关联、版本接纳、状态权限及预算边界齐全 |
| 5 | 在 4 分基础上验证了所需角色与交接边界；混合模式、永久 Manager 和跨系统通信属可选 |

## 5. 进阶维度 8-14

### 维度 8：记忆管理

按任务需要评当前上下文、会话状态、任务笔记和长期记忆。只需会话连贯或任务续作时，不因缺少长期组件扣分；完全不需状态复用时记不适用。长期记忆及各类型只检查实际需要的部分。

检查项：
- [ ] 区分当前上下文、可持久化任务状态、稳定记忆与正式知识，说明所需层及理由
- [ ] 有有效预算与必要加载、剪枝或压缩规则，保留目标、约束、证据和动作状态
- [ ] 需要续作时，受控保存与恢复真实进度、未决事项及剩余预算，不盲目重做外部动作
- [ ] 需要长期记忆时，写入有长期价值与可信证据、先查重，未核实推断不写成事实
- [ ] 读取、写入与输出按可信作用域授权，必要记忆可按引用、关键词或语义方式取用
- [ ] 适用的更新、冲突、时效、来源、删除和索引同步有治理规则

反模式：长窗口当持久化；任务进度当长期偏好；无来源或跨用户记忆；摘要提高外部指令权限；压缩丢约束、重置预算；只写不治理；为得分配齐长期组件或全部记忆类型。

| 分 | 标准 |
|---|---|
| 0 | 需要连贯、续作或记忆复用却缺失 |
| 1 | 有历史或记录，但边界不清，关键状态容易丢失 |
| 2 | 基本可用，适用的预算、更新、恢复或作用域有明显缺口 |
| 3 | 所需信息层和取用清晰，适用的压缩、可信写入或治理仍有缺口 |
| 4 | 必要预算、加载、保留、作用域及适用的恢复或记忆治理齐全 |
| 5 | 在 4 分基础上验证了必要策略的效果与失败边界；长期记忆、全部记忆类型和反思改进属可选 |

### 维度 9：学习与适应

只评确需根据跨任务经验或变化更新行为的能力；任务内修正属于短期改进，与跨任务学习分开。静态策略可经维护者离线改进；自主写代码、独立监督Agent、多样性搜索、长期记忆和微调属可选。

检查项：
- [ ] 明确需要何种适应，信号、真实结果、根因假设及改进目标分开，反馈或批准不直接作正确标签
- [ ] 信号来源/作用域、授权、版本及必要数据治理清楚，样本偏差与不确定性不被忽略
- [ ] 提案有可核对证据、对象/基线、具体改动、验证、风险和负责人，根因可未知/多因，不凭枚举保证正确
- [ ] 可信层限制修改范围和生效，按实际风险决定隔离与审批，目标、权限、评分器和门禁只能由可信层调整
- [ ] 改动在目标失败类及其他必要类和未用于调优的数据上比较，保留失败、资源及覆盖，不只挑最好结果
- [ ] 记录版本、效果与回退/依赖条件，必要整理重复/失效规则，迭代有预算和停止出口

反模式：静态即零分；自主Agent必须微调；memory按文件名自动安全；批准即质量；自改评分器刷绿；不验证就生效；强制专门学习小队；单条回退不查后续依赖。

| 分 | 标准 |
|---|---|
| 0 | 确需跨任务适应却没有有效信号或更新路径 |
| 1 | 只零散积累反馈，目标与证据不清 |
| 2 | 有基本调整，评测、治理或生效边界有明显缺口 |
| 3 | 改进流程清楚，适用的独立验证、授权或回退仍不足 |
| 4 | 必要信号核验、证据提案、受控生效、版本比较与停止/回退边界齐全 |
| 5 | 在4分基础上验证了所需适应效果和退化边界；自主修改、多Agent和训练权重属可选 |

### 维度 10：异常处理与恢复

按实际外部调用、续作和副作用评估，回滚、补偿、自纠正与永久运行设施按需配置。能正确停止或交付允许部分结果也是可靠行为。

检查项：
- [ ] 依据真实格式、错误和执行语义分类，区分未执行、已执行及结果未知，超时或5xx时动作仍可能已执行
- [ ] 瞬态重试、格式修正、质量修复和回退分别定义，初次/追加调用及多层重试有统一计数和停止出口
- [ ] 副作用重试前核对已发生动作或真实幂等保障，动作键、参数、作用域及去重期限不混淆
- [ ] 需恢复时保存可信任务、版本、审批、动作和剩余预算，重新校验授权及执行所有权，不重做完成项或重置额度
- [ ] 按需定义降级、取消、迟到结果、事务回滚或补偿，不可逆副作用如实记为已发生；关键失败如实报告为失败
- [ ] 必需门控故障阻止依赖动作，错误与缺口可定位并有负责人或明确返回

反模式：所有错误都重试；超时即失败重发；多层重试相乘；新动作键重复旧副作用；重启预算归零；所有失败都要求事务回滚；持续运行才算可靠。

| 分 | 标准 |
|---|---|
| 0 | 需要处理失败却没有有效检测和出口 |
| 1 | 只捕获异常，事实与后续不清 |
| 2 | 基本处理可用，分类、动作语义或上限有明显缺口 |
| 3 | 处理路径清楚，适用的结果未知、恢复或降级边界仍不足 |
| 4 | 必要分类、有限处理、动作核对、状态及安全结束边界齐全 |
| 5 | 在4分基础上验证了所需失败与恢复路径；回滚和补偿属可选，高度不确定时允许安全中断 |

### 维度 11：人机协同

按风险及业务需要评估澄清、审批、监督或接管。常规已授权低风险动作可自动执行，每任务签需求、唯一Manager、全部人工审核和持续学习闭环属可选。

检查项：
- [ ] 介入有明确触发、负责人、允许决定、等待期限及拒绝/晚到回复出口
- [ ] 人取得必要原始目标、真实产物或动作参数、版本、依据与缺口，不用全量历史或模型通过摘要替代
- [ ] 请求与可信任务、作用域、审批人资格和有效决定关联，批准只来自明确决定，已读和修改反馈另作记录
- [ ] 执行前重验授权、参数/版本和决定有效性，禁止政策在批准后仍然有效，批准只覆盖所绑定的动作
- [ ] 受控入口统一记录与恢复，可多入口但不绕过；停止和事故接管不依赖失效模型
- [ ] 敏感材料按审批人可见范围提供，等待期间释放昂贵资源，恢复沿用累计总预算

反模式：审批疲劳；自报高信心免审批；已读即批准；批准旧正文发送新版；要求人与每个执行者搬消息；单一接口变成单点故障。

| 分 | 标准 |
|---|---|
| 0 | 必要人工决定缺失，高风险或歧义无安全出口 |
| 1 | 有人工概念，缺触发和负责人 |
| 2 | 基本介入可用，材料、决定或超时处理有明显缺口 |
| 3 | 触发与材料清楚，适用的可信绑定、拒绝或恢复仍不足 |
| 4 | 必要介入、真实材料、资格、决定绑定、期限、授权及恢复齐全 |
| 5 | 在4分基础上验证了所需审批与介入边界；专家匹配平台、唯一Manager和学习闭环属可选 |

### 维度 12：推理技术

按任务需要选择推理方式，评分与方法数量无关。可审计指依据、动作、实际结果和关键决策摘要可追溯，内部思维链无需公开。各检查项先判断适用性，无需工具、修正或多候选比较时注明理由即可，照常给分。

检查项：
- [ ] 推理方式与任务需求匹配，简单任务未为凑模式增加循环
- [ ] 需要外部事实时使用真实工具结果，而非靠模型自行补齐
- [ ] 需要纠正时，有具体校验、测试或评审反馈，且次数有上限
- [ ] 关键依据、工具动作、实际结果和检查结论可追溯
- [ ] 推理预算有边界，格式修正和重新生成都计入总额

反模式：用多种方法组合证明设计先进；把公开完整思维链当验收条件；需要核实事实却只让模型多想几轮；无反馈反复自评。

| 分 | 标准 |
|---|---|
| 0 | 需要推理支持却缺失，关键结论无依据 |
| 1 | 只有笼统的「逐步思考」提示，未对应任务需求 |
| 2 | 方法基本匹配，但适用的验证、追溯或预算设计明显缺失 |
| 3 | 方法匹配，有依据与检查设计，适用的反馈或边界仍有缺口 |
| 4 | 必要方法、验证、追溯和预算边界齐全，组合多种方法属可选 |
| 5 | 在 4 分基础上，代表性及失败案例验证了必要方法的效果和边界 |

### 维度 13：安全防护

按实际数据、动作与接收者设计必要防线。内容和执行都重要，纯生成应用的执行沙箱按需配置；正则、内容过滤、容器和提示词各自只覆盖部分风险。

检查项：
- [ ] 输入、外部资料和工具返回保留来源/信任边界，校验类型、范围和大小；摘要不提升指令权限
- [ ] 可信身份及用户/服务对对象和数据的授权在执行与输出边界检查，新能力默认无权限
- [ ] 工具和实际参数受可信门控，明确禁止优先，ASK在有效批准前阻止；授权另行检查
- [ ] 按需限制文件、网络、挂载、进程、资源与配置写入，路径/URL及检查后变更按实际执行语义约束
- [ ] 密钥在可信层管理，任意代码可读的环境变量视为已暴露；输出和日志按接收者范围保护敏感信息
- [ ] 必需安全或审计组件故障默认拒绝，Agent不能修改自己的可信政策或权威审计记录
- [ ] 有实际越界和拒绝路径验证，拒绝时工具未执行，不只看警告或模型自述

反模式：正则保证无注入；ASK只告警；用户批准覆盖DENY；服务账号共享全部数据；沙箱自动保证凭据安全；追加文件即不可篡改；安全组件出错时放行。

| 分 | 标准 |
|---|---|
| 0 | 实际风险无必要安全边界 |
| 1 | 只有提示词约束，没有可信执行保障 |
| 2 | 有局部防护，身份、数据或执行范围有明显缺口 |
| 3 | 分层设计清楚，适用的凭据、故障拒绝或审计边界仍不足 |
| 4 | 必要信任、身份授权、执行/输出、凭据、策略及故障边界齐全 |
| 5 | 在4分基础上验证了所需对抗与越界路径；特定沙箱、实时平台和全量日志属可选 |

### 维度 14：评估与监控

按质量保证与实际部署需要评估。评测方案先于平台，离线检查、周期复核或人工抽查可足够；实时看板、A/B平台、自动告警和统一的指标数量都属可选。已有维度按需选取规则保持不变。

检查项：
- [ ] 业务目标与系统标准相匹配，用例、执行、评分和准入分开，覆盖主流程、边界及必要失败场景
- [ ] 来源/版本/夹具/执行协议与必要数据分组、留出和治理明确，历史或合成输出不天然作标准答案
- [ ] 必要输出、真实终态、过程与资源可验证，Mock/集成/用户验收各自证据范围清楚
- [ ] 代码评分器有正反例与缺数据检查，模型评分按标准及人工样本校准，评分无效不判业务通过
- [ ] 计划/已运行/有效评分与分母、未运行/失败/全部重跑保留，重复指标、独立假设与不确定性正确
- [ ] 基线、候选、数据及评分版本可比，必需检查绑定版本，待定/旧检查不验收新产物，硬失败不被平均分抵消
- [ ] 线上监控按实际风险写指标口径、窗口、采样、缺数据、负责人和响应，变化可下钻并回流核验案例

反模式：只有HTTP200；只看文字不查动作；缺评分数据就通过；pass^k当单次成功率；刷最好一次；平均掉严重失败；总分替代上线许可；没有实时看板即低分；富集坏例估全量率。

| 分 | 标准 |
|---|---|
| 0 | 需要质量评估却没有有效标准与检查 |
| 1 | 只有日志或印象判断，缺评测依据 |
| 2 | 基本指标与用例可用，执行、评分、分母或证据有明显缺口 |
| 3 | 体系与比较清楚，适用的校准、版本门禁或线上响应仍不足 |
| 4 | 必要用例/执行/评分、统计、版本比较、准入及适用的监控回流边界齐全 |
| 5 | 在4分基础上验证了所需评测和监控边界；实时看板、A/B和专门评测平台属可选 |

## 6. 扩展维度 15-21

### 维度 15：标准化工具接口（MCP）

仅在实际使用 MCP 或明确需要标准化跨客户端、跨服务接入时评估；少量本地函数或现有 SDK 足够时记不适用，不因未引入协议扣分。

检查项：
- [ ] 接入方式有复用或现有服务依据，参数与返回满足 Agent 需求；已有清晰接口无需再次包装
- [ ] 客户端支持版本、服务来源和真实定义已确认，结果及必要证据可读取
- [ ] 凭据与身份来自可信系统，工具允许清单及服务端授权分别检查
- [ ] 有明确超时和错误去向，任务完成以结果检查为准，连接或提交成功只是过程
- [ ] 区分资源、工具和提示模板的用途，按实际支持范围使用，三种能力按需选用

反模式：简单应用为评分引入 MCP；相信协议自动保证安全；全量暴露服务工具；把说明模板当作已执行操作；未经核对猜测工具名或参数。

| 分 | 标准 |
|---|---|
| 0 | 明确需要标准化接入却缺失或无法使用 |
| 1 | 接入定义含糊，兼容性或工具契约未经核对 |
| 2 | 已接入，但实际契约、授权或错误处理存在明显缺口 |
| 3 | 连接与能力选择合理，适用的安全、超时或失败处理仍有缺口 |
| 4 | 兼容范围、真实定义、允许清单、授权、返回、错误和超时齐全 |
| 5 | 在 4 分基础上验证了所需接入、权限和失败边界；多服务组合和动态扩展属可选 |

### 维度 16：目标设定与监控

只在长任务、多阶段交付或需要跟踪进度时评估。简单任务有可检查的完成标准即可，记不适用；量化指标和独立监控机制属可选。

检查项：
- [ ] 目标具体、可衡量、可实现、相关、有时限
- [ ] 由独立于执行者的机制判断是否达成
- [ ] 设有最大迭代次数或超时
- [ ] 有量化指标和成功标准
- [ ] 未达目标时有升级或回退机制

反模式：同一模型既执行又评判；监控循环没有终止保护；目标模糊、无法衡量。

| 分 | 标准 |
|---|---|
| 0 | 没有目标概念 |
| 1 | 有隐含目标，无监控和完成判断 |
| 2 | 只做一次「生成、评估」，标准模糊 |
| 3 | 有目标、进度和完成判断，适用的验收、停止或失败返回仍有缺口 |
| 4 | 目标规范、独立检查、次数或时间上限、失败去向和完成证据齐全 |
| 5 | 在 4 分基础上验证了目标偏离、阻塞和超限场景；多角色和重规划属可选 |

### 维度 17：知识检索（RAG）

只在需要定位外部知识支撑生成时评估。材料已完整提供且无需检索时记不适用；引用读取、关键词、向量或混合方式按实际需求选择，不以技术数量或多步搜索加分。

检查项：
- [ ] 来源与检索方式符合问题，简单方式足够时直接使用，向量、混合检索和知识图谱属可选
- [ ] 权限、用户指定的时间和业务条件得到保留，默认假设的扩展有说明
- [ ] 候选数量、读取范围与预算受控；需要分块或融合时保留上下文并验证质量
- [ ] 当前正文、摘要与索引版本可核对，适用的更新、删除和延迟处理已明确
- [ ] 证据实际支持结论，必要时回读原文，能处理矛盾、过期、空结果与知识缺口
- [ ] 输出具体来源与证据边界，摘要标明为摘要，相似度与正确性分开

反模式：向量等同 RAG；无权限过滤；为搜到结果偷偷移除用户条件；静默使用旧索引；有引用但不支持结论；只召回片段就声称查全；复杂检索为评分而增加。

| 分 | 标准 |
|---|---|
| 0 | 需要外部知识却未获取，关键结论无依据 |
| 1 | 有检索但来源、范围或实际证据不清 |
| 2 | 方法基本匹配，质量控制、证据或时效有明显缺口 |
| 3 | 检索与证据链清晰，适用的权限、冲突、版本或缺口处理仍不足 |
| 4 | 必要范围、预算、证据引用及适用的更新和失败处理齐全 |
| 5 | 在 4 分基础上验证了所需检索质量、引用支持和边界；向量、混合和多步检索属可选 |

### 维度 18：Agent 间通信（按需采用 A2A）

按实际进程内、跨进程或跨系统通信评估。共享状态或直接调用足够时不因缺网络协议、动态发现、异步任务、多模态或已读状态机扣分；没有额外通信需求可记不适用并说明。

检查项：
- [ ] 方式与必要信息交换相匹配，允许接收者、字段、任务作用域和结果取得方式明确
- [ ] 数据共享与任务触发分别定义，通知到达、消息确认与业务验收不混淆
- [ ] 实际调用身份、端点或状态访问受可信系统授权，能力卡不作为信任证明
- [ ] 适用的版本、超时、失败、重复与迟到处理明确，直接调用无需邮箱状态机
- [ ] 确需标准协议时核对支持版本与真实契约，自制 HTTP 骨架按自制接口描述

反模式：简单固定链为评分引入 A2A；能力发现等同授权；通知到达即验收；三态消息保证恰好一次；所有材料广播给所有角色。

| 分 | 标准 |
|---|---|
| 0 | 必要信息无法可靠取得或传给接收者 |
| 1 | 能传信息但字段、接收者或作用域不清 |
| 2 | 基本通信可用，真实契约、权限或结果处理有明显缺口 |
| 3 | 信息交换清楚，适用的触发、版本、失败或确认语义仍不足 |
| 4 | 必要字段、可信关联、访问范围、结果取得及适用的异步或兼容边界齐全 |
| 5 | 在 4 分基础上验证了所需通信与失败边界；动态发现、标准协议、异步和多模态属可选 |

### 维度 19：资源感知优化

评估任务质量、时限、用量和成本是否受控。固定模型足够时不因缺动态选择、自动回退、负载均衡或缓存加分项扣分。

检查项：
- [ ] 模型及必要回退符合质量、隐私、工具兼容与时限，切换不绕过拒绝或重置额度
- [ ] 定义适用的调用、token、费用、时间、并发等上限与真实计数口径，请求数有用但不单独保证金额
- [ ] 全分支、SDK/框架重试、委派与汇总共用总预算，调用前统一预留，之后结算，未知用量保守留额
- [ ] 必要交付/检查有预留，超限或预算控制失效有安全出口；封顶由调用前的强制检查保证
- [ ] 粗估与硬上限区别明确，硬金额限需可约束计费上界，缓存和折扣按真实服务核实；启用前缀缓存时静态前缀与工具顺序稳定、动态内容置后

反模式：固定一个模型即零分；盲切更便宜模型绕过隐私；分支重复消费额度；只在工具前查模型账；固定字符换算称精确计费；最后总结透支预算。

| 分 | 标准 |
|---|---|
| 0 | 所需资源无约束，可能无界消耗 |
| 1 | 知道成本但只靠提示词或事后记录 |
| 2 | 基本预算可用，计数、预留或停止有明显缺口 |
| 3 | 选择与预算清楚，适用的共享额度、未知用量或回退仍不足 |
| 4 | 必要质量/时限、全局计数、预留结算、软硬限与超限出口齐全 |
| 5 | 在4分基础上验证了所需预算和性能取舍；多模型、动态路由和缓存属可选 |

### 维度 20：优先级排序

只在资源竞争、截止期或重要性冲突需要取舍时评估；固定顺序或 FIFO 足够时记不适用。规则足够不加模型评分，只有相关条件变化才要求重排。

检查项：
- [ ] 排序的必要性和标准明确，依赖、权限、输入、资源与预算先决定任务是否就绪
- [ ] 调度在就绪集合中选任务，分支派发前由宿主统一检查并预留所需额度
- [ ] 规则、平局及适用的最大等待处理明确，不凭模型主观分数替代授权或依赖
- [ ] 必要事件变化可调整顺序，已执行任务抢占或取消有允许边界，目标和总预算保持累计

反模式：高优先级越过审批或依赖；各分支同时消耗同一剩余额度；低优先级无限饥饿；固定任务为评分加动态重排。

| 分 | 标准 |
|---|---|
| 0 | 需要资源或时限取舍却没有有效选择规则 |
| 1 | 有顺序但标准或就绪约束不清 |
| 2 | 基本排序可用，资源、依赖或公平性有明显缺口 |
| 3 | 标准和调度清晰，适用的预算、等待或变化处理仍不足 |
| 4 | 必要就绪过滤、排序、平局、额度与适用等待或重排规则齐全 |
| 5 | 在 4 分基础上验证了所需取舍与失败边界；多层排序、模型评分和动态重排属可选 |

### 维度 21：探索与发现

仅在存在需假设与验证的未知问题时评估，普通事实检索可记不适用。多 Agent、知识图谱和复杂搜索算法属可选。

检查项：
- [ ] 假设、支撑与反证、验证方式和当前结论能区分并追溯
- [ ] 按任务需要考虑替代解释，模型的新观点和置信分数经验证后才算证据
- [ ] 验证在授权范围内执行，不因探索扩大工具、实验风险或业务目标
- [ ] 所需证据、范围、信息增益或资源停止条件明确，未验证判断保留不确定性

反模式：未知就是无限搜索；提出假设不验证；自报置信度代替证据；为评分建立图谱或探索小队。

| 分 | 标准 |
|---|---|
| 0 | 需要调查未知却不提出或核对有效假设 |
| 1 | 有猜测，缺证据和验证设计 |
| 2 | 基本调查可用，验证或结论边界有明显缺口 |
| 3 | 假设与证据清晰，适用的替代解释或停止处理不足 |
| 4 | 必要假设、验证、证据追溯、不确定性、范围和停止规则齐全 |
| 5 | 在 4 分基础上验证了探索质量与边界；多 Agent、图谱和复杂搜索算法属可选 |

## 7. 交付前硬性检查

以下任一项不满足，记为严重问题：

- [ ] 写明了为什么不选更简单的架构档位
- [ ] 有可衡量的成功标准与主流程、边界、失败用例草案及验证计划；草案标明为草案，未运行/无效检查分别记录、不计入通过
- [ ] 每个 Agent 有停止条件，所有循环（反思、重试、Agent 主循环）有次数或时间上限
- [ ] 每条 Agent 间交接有字段定义和校验规则
- [ ] 每个 Agent 的工具和读写权限遵循最小权限
- [ ] 不可逆或高风险操作按政策有审批或代码拦截；有效批准绑定真实请求，身份与对象授权另行检查
- [ ] 有成本或调用量上限
- [ ] 失败时有宿主真实事件、必要状态与产物引用可定位；无需模型自述或全量敏感日志
