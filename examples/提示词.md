# 示例提示词

这些句子演示怎样把 [SKILL.md](../skills/agent-system-design-cn/SKILL.md) 用起来。它们不是安装证明。发布本仓库时没有在具体宿主里加载过这个 Skill，也不能从提示词本身推断宿主已经识别它。

信息不够时，Skill 要求一次最多问 3 个关键问题。只读材料能确定的事，提示词里不要再让它向人追问。

## 新设计

```text
请按 Agent 系统设计 Skill 处理下面的需求。先判断需不需要多 Agent，再设计它们如何协作。信息不够时最多问 3 个问题。只交付设计，不要写运行时代码，不要部署。

需求：根据一封客服邮件和一份内部口径，把草稿分成「可直接发送」「需人工修改」「信息不足」三类，并列出修改要点。邮件和口径都会随任务给出。
```

## 评审已有设计

```text
请评审下面的 Agent 设计，只输出《Agent 设计评估报告》。先判断类型，再选择适用维度。没有运行证据的不要写成已验证；材料不足就标待核实，并且不打分。不要另起一套多 Agent 方案。

[在这里粘贴设计文档、提示词或架构说明]
```

## 对照本仓库的工作流示例

```text
请阅读 examples/word-counts-workflow.md。这是针对 word_counts 函数的固定流程：代码生成，然后审查，然后按需修复。架构档位保持工作流，不要改成多 Agent。文中的分数是留空的，请保持留空，不要补实测分数、时延或通过结论。请指出 gate、失败去向、停止条件、预算、安全和评测各自写在哪一节。
```

## 改造已有流程

```text
下面是一个已经用固定脚本处理表格的流程。请先还原现状，只设计确有必要的变化；没有改的部分写「沿用现状」。如果普通代码已经够用，请在架构选型处停止，并说明理由。不要为了采用 Agent 而增加角色。

[在这里粘贴现状]
```
